# Artifact manifest — released result files, regenerating scripts, and manuscript role

> **Code-only release: the manuscript is under review.** The score files, the generated results
> and the de-identified clinician tables this document refers to are added on acceptance, so
> `data/`, `results/` and `adjudication/` are not in this repository yet. `RESULT_SHA256SUMS.txt`
> commits now to the bytes that will arrive. Editors and reviewers hold the complete artifact.

This is the file-level recompute map for the artifact package cited in the
paper's §4.7 (Implementation and computing environment). Per-file SHA256
checksums of all released result and score files are in
`RESULT_SHA256SUMS.txt` (verify with `sha256sum -c RESULT_SHA256SUMS.txt`).

**One-command reproduction:** `python code/reproduce.py` verifies the checksums and asserts every
headline certified number (tab:joint, the real-clinical arm §5.12, the decision value §5.5)
matches the released JSONs; `python code/reproduce.py --recompute` additionally regenerates the
headline cells from the released scores and runs every self-checking script (backing up and
restoring released files, so the checksum set stays intact). Environment pin: `requirements.txt`
(Python 3.12, CPU-only certify path); step-by-step guide: `docs/REPRODUCE.md`.

All certification runs through the shared CPU library `certify.py`
(no GPU, no network); scoring scripts run vLLM. Seeds: calibration split 7,
prevalence draw 2024, score generation 20260609 (main paper §4).

Scope: the table below maps every result file the manuscript draws on.
`RESULT_SHA256SUMS.txt` defines the released result/score file set; it also
covers additional supporting result files not cited by the manuscript (e.g.
the per-judge battery input files feeding `aggregate_battery.py`). Remaining
working files in this directory sit outside that checksummed release set and
are documented in the per-experiment notes listed at the end of this file.
