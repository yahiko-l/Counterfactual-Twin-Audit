# Reproducing the ψ_g paper (headline certified numbers)

> **Code-only release: the manuscript is under review.** The score files, the generated results
> and the de-identified clinician tables this document refers to are added on acceptance, so
> `data/`, `results/` and `adjudication/` are not in this repository yet. `RESULT_SHA256SUMS.txt`
> commits now to the bytes that will arrive. Editors and reviewers hold the complete artifact.

This directory is the versioned artifact package for the paired-hallucination-risk (ψ_g) paper. The
certified numbers are regenerated by released CPU scripts under declared seeds: the score-derived cells from
released score files, the clinician-derived cells from the de-identified adjudication tables. Released files
are checked against a per-file SHA256 manifest, and one command verifies that chain. No certificate
recomputation invokes a model-serving stack.

## Quick start

```bash
python -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt   # Python 3.12
python code/reproduce.py              # layers 1+2: checksums + paper<->artifact  (seconds, read-only)
python code/reproduce.py --recompute  # + layer 3: regenerate from the released scores (CPU-minutes)
```

Exit code `0` iff every checked value matches. `--recompute` backs up and restores each released file it
regenerates, so the checksum set is byte-identical afterwards.

`reproduce.py` checks three layers:

| Layer | What it proves | Cost |
|---|---|---|
| **[1] integrity** | every published result and score file is unmodified. Run it through `reproduce.py`, not as a bare `sha256sum -c`: the manifest also lists the entries named in `docs/WITHHELD_FROM_RELEASE.txt`, which are not part of the public package, so a bare check reports them as failures | seconds |
| **[2] paper ↔ artifact** | the headline joint table (tab:joint), the real-clinical arm (§5.12), and the decision-value result (§5.5) equal the released JSONs to displayed precision | seconds |
| **[3] script ↔ artifact** (`--recompute`) | re-running `m3_combined.py` + `m6_robust_leaf.py` from the released scores regenerates the headline cells; the self-checking scripts (`m_pairedlift`, `R050_decision_value`, `M4_certify_real_arm`, `M5 --dryrun`, `worstcase_relabel_check`) all pass | ~seconds (CPU) |

## What reproduces what

The full file → regenerating-script → manuscript-role map is **`docs/ARTIFACT_MANIFEST.md`**; the per-file
checksums are **`RESULT_SHA256SUMS.txt`**, verified by `reproduce.py` layer 1, which skips the
`docs/WITHHELD_FROM_RELEASE.txt` entries. The headline joint-certification cells (tab:joint)
come from:

| Certified quantity | Released file | Script |
|---|---|---|
| τ̂, ρ̂, m_c, ψ̂_g, exact ψ_g LCB | `m3_combined_results.json` | `m3_combined.py` |
| robust ψ̄_g LCB (Hoeffding–Bentkus) | `m6_robust_leaf_results.json` | `m6_robust_leaf.py` |
| marginal F₁ and paired lift Δψ | `m_pairedlift_results.json` | `m_pairedlift.py` |
| decision value (Fréchet [0,1] + re-pairing) | `R050_decision_value_results.json` | `R050_decision_value.py` |
| real-clinical arm two-leaf corroboration | `M4_real_arm_certificate.json` | `M4_certify_real_arm.py` |
| threshold-grid multiplicity (§4: γ-floor 28→26/family ⇒ 234/78; 252-robustness) | `grid_multiplicity_check.json` | `verify_grid_multiplicity.py` |

All certification is **CPU-only, no GPU, no network** through the shared library `certify.py`. Seeds are fixed
in code: calibration split `7`, prevalence draw `2024`, real-arm S_R draw `20260710`; the candidate threshold
grid is 28-point on `D_sel`; the four-family budget is (δ_global, δ_mass, δ_ψup, δ_lower) = (0.025, 0.025,
0.01, 0.04), δ_total = 0.10. These match the protocol-constants table of the paper's §4.

## Regenerating the raw scores (optional, GPU)

The certified numbers reproduce from the released score CSVs (`scores_strong.csv`,
`scores_strong_artificial.csv`, `scores_pilot.csv`) without any model. To regenerate those CSVs from model
outputs you need `vllm==0.22.1` (+ the five environment fixes in the paper's Supplementary reproducibility
section) and the pinned detector checkpoints (`Meta-Llama-3-8B-Instruct`, `roberta-large-mnli`); the scoring
scripts are `score_strong.py` / `score_generic.py`. This step is not needed to verify the paper.

## Artifact taxonomy

- **Scripts** (`*.py`) — `certify.py` (shared library) + the `m*/M*/R050/reproduce` recompute scripts.
- **Released results** (`*_results.json`, `*.json`) — the certified numbers; all in `RESULT_SHA256SUMS.txt`.
- **Released scores** (`scores_*.csv` listed in the checksum file) — detector scores keyed by integer id.
- **Blinded human-adjudication instruments** — the published form is `adjudication/`, which carries
  derived labels and HMAC row identifiers only and reproduces the clinician-derived counts underlying the
  paper's headline claims. The finer descriptive statistics, and the 1,232-row census read, are reproduced by
  the analyst scripts in the main tree rather than by `recompute_adjudication.py`.
  The underlying sheets and unblinding keys are **available from the authors** and are **not** part of this
  package: the B4 blind, filled and key sheets are answer-bearing and carry an `annotator_id` column, and the
  real-arm equivalents (`M3_*_key.csv`, `../MEDHALU_annotation_handoff/`, `pilot_sanity_KEY.json`) are
  analyst-only. `docs/WITHHELD_FROM_RELEASE.txt` names each withheld file and its reason.

## Scope

The MedHallu headline cells are split-validated certificates. The real-clinical arm (§5.12) is a **nominal,
in-sample corroboration, not a split-validated certificate** (same-sample selection); `M4_certify_real_arm.py`
and its JSON label it as such. The full-S_R clinician read was carried out by `M6_certify_SR_audit.py` and
the `M6F_*` census scripts. **`M5_certify_SR_clinician.py` and `B_FULL_SR_HANDOFF.md` are superseded and must
not be used**: that earlier one-per-source sheet matched M4's ref-NLI picks only at chance, a wrong-stream bug
that its `--dryrun` path masked. `docs/ARTIFACT_MANIFEST.md` records the same supersession.
